## 稳定达标线

以下四项须同时满足，才算稳定达标：

1. Nightly E2E 连续七天全绿。
2. 连续三轮真实模型基准零人工介入。
3. 用户连续使用七天，没有停滞事故。
4. 冻结期间没有未经批准的功能。

用户接受了 S1 的结果，尽管 Linux Electron/Viz 根因尚未查明。该风险接受只关闭 S1 包，不构成稳定达标线中任何一项的证据。S1 任务仍须保留原始 CI 结果、失败和 `NOT RUN` 记录。

## 界面达标线

以下四项须同时满足，才算界面轨达标：

1. 字号、圆角、行高和字重档位已收敛，设计规格同步。
2. 弹窗和菜单使用基础组件。
3. 用户已看图确认前三个监督界面。
4. 每项 UI 改动都附前后截图。

界面与稳定两条验收线分别跟踪。截图须使用已批准的夹具方式；每轮取图都要用户明确授权，且不得截取用户正在运行的应用。

## 规则归属与交付

产品行为由对应产品规格定义。架构冻结边界、公共契约、数据归属、安全边界或发布流程变更的理由记录在 ADR 中。每个包的报告注明行为和文件变更、实际运行的检查及结果、每项未运行检查的 `NOT RUN` 状态，以及剩余风险。没有用户指令，不更新看板和路线图。

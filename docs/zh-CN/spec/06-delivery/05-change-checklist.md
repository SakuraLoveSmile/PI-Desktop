# 05. 变更检查清单

> 完成变更的可执行检查清单。每一项都链接到 [03-ai-development-workflow.md](/zh-CN/spec/06-delivery/03-ai-development-workflow) 中拥有该规则的条目；本文件跟踪完成度，不定义策略。

## 0. GitHub Issue 准入

当提示包含 GitHub issue URL 或无歧义的 issue 编号时：

- [ ] 已获取 issue 标题、正文、标签、评论和状态。
- [ ] 已对照当前代码独立核实所报告的问题。
- [ ] 缺陷已分类为 `confirmed regression`、`confirmed existing defect`、`already fixed`、`expected behavior`、`environment-specific failure` 或 `insufficient evidence`。
- [ ] 仅在问题确认之后才开始实现。
- [ ] 问题不存在：已发布核实评论，结论明确时关闭，无法定论时保持打开并说明已尝试的内容。
- [ ] 问题确认：已实现最小一致修复，集成后发布处理结果评论并关闭该 issue。
- [ ] 评论使用 issue 的语言；未触碰无关 issue；未从链接推断 push。

参见 [R5](/zh-CN/spec/06-delivery/03-ai-development-workflow#r5-—-先核实链接的-github-issue-再回复并关闭)。

---

## 0.1 GitHub Pull Request 准入

当提示包含 GitHub pull request URL 或无歧义的编号时：

- [ ] 已获取 PR 标题、正文、文件、提交、评论、检查、草稿状态、base/head 和关联 issue。
- [ ] 已核实根因门槛：真实且在范围内的问题、最小一致修复、与基线、安全边界和架构兼容。
- [ ] 未把后续打磨（规格、测试、i18n、E2E 文档、风格、命名）当作合并阻塞项，除非它们是证明根因所必需的。
- [ ] 已先合入根因完整的 PR，并保留贡献者提交与作者身份。
- [ ] 落地阻塞只收到了最小的追加提交；贡献者分支未被 force-push。
- [ ] 后续工作在更新后的 `main` 上以新请求开始。
- [ ] 门槛未通过或存在危害阻塞：未合入，未给出「方向没问题」式的通过，已用 PR 的语言发布证据评论。
- [ ] 除非明确要求，未合入草稿 PR；未触碰无关 PR；未从链接推断无关的远程发布。

参见 [R6](/zh-CN/spec/06-delivery/03-ai-development-workflow#r6-—-链接的-pull-request-仅在根治问题且改动最小时才合入)。

## 1. 请求启动

- [ ] 已声明等级；T0 跳过任务记录、候选 E2E 和完整交付报告。
- [ ] 已识别并保留现有未提交工作。
- [ ] 已获取 `origin/main`，并据此创建专用 `<type>/<YYYYMMDD>-<task-id>-<slug>` 分支和工作树。
- [ ] 工作树位于 `AGENTS.md` 声明的中央根目录下并以本任务命名；已检查工作状态、`git worktree list` 和任务归属。
- [ ] 当前分支不是 `main`；未复用其他请求的分支或工作树。
- [ ] 已复用宿主工具链、包存储、缓存和忽略的配置；未为 E2E 安装单独环境；只有可变或不兼容的状态保留在工作树本地并被忽略。
- [ ] 已记录交付范围：仅提交停留在请求分支；push、PR、合并和发布需要明确授权。

---

## 2. 任务记录与证据

T1 与 T2 记录这些；T0 跳过。

- [ ] 存在一份权威任务记录：现有计划或 `docs/tasks/` 下的文件。
- [ ] 已记录范围、冻结决策、分支/工作树/目标、验收场景和代码版本。
- [ ] 已记录实际验证、缺失验证、剩余工作和运行时资源。
- [ ] 状态设为 `未开始`、`实现中`、`待体验` 或 `已验收`；只有用户明确确认才能设置 `已验收`。
- [ ] 恢复时：已重新核实路径、HEAD、索引、未提交工作和下一步动作。

---

## 3. 影响分析

- [ ] 已列出可观察行为变更。
- [ ] 已按[规格更新矩阵](/zh-CN/spec/06-delivery/03-ai-development-workflow#_10-规格更新矩阵)按路径列出受影响的规格。
- [ ] 已评估架构边界、用户可见或协议可见行为，以及里程碑交付物。
- [ ] 按风险而非 diff 大小选择验证范围。
- [ ] 已在任务记录中记录计划和受影响表面。

---

## 4. 规格同步

- [ ] 每个受影响的规格都已按新行为更新。
- [ ] 架构边界变更在 `docs/adr/` 中有 ADR。
- [ ] 实现默认值变化更新了 `decisions-log.md`。
- [ ] 基线冻结决策变更附有 ADR 和版本提升。
- [ ] 交叉引用和锚点仍可解析。
- [ ] 策略文件保持在其字节预算内并保留必需锚点；`pnpm check:agent-policy` 通过。

---

## 5. 测试与 E2E 文档

- [ ] 用户可见或协议可见行为：已在 [04-e2e-test-plan.md](/zh-CN/spec/06-delivery/04-e2e-test-plan) 中新增或更新 E2E 场景。
- [ ] 场景遵循模板，且可追溯性矩阵与生成的索引是最新的。
- [ ] 当变更风险需要时，已新增或更新单元测试或集成测试。
- [ ] 新测试断言行为或稳定合约，而不是仓库源码或 CSS 文本；`pnpm check:test-quality -- --base <base>` 针对实际基础通过。
- [ ] 退役的源码断言降低了已登记清单；已记录替代覆盖；已移除过时测试和场景 ID。
- [ ] 运行时领域测试与辅助代码保持在 800 行预算内。
- [ ] 纯文案、i18n 或样式豁免记录受影响表面的验证与剩余风险；它不覆盖交互、响应式、无障碍、运行时规则或内容布局变更。
- [ ] T1/T2：最小的针对性本地检查已通过，或本地验证被评估为不必要。
- [ ] T1/T2：相关 E2E 套件已在包含最新 `origin/main` 的候选上运行，先于合并或仅提交式完成；T0 与仅文档变更豁免。
- [ ] 托管精确 SHA 通道：获得授权的推送或 PR 可以先于门禁，但其结果必须在合并前取得，且 PR 集成作业单独观察。
- [ ] 本地 task-candidate E2E 复用了宿主环境；未为 E2E 单独安装依赖或创建第二套运行时环境，任何宿主缺失或不兼容的原因已记录。
- [ ] 证据绑定被测 SHA、基础版本、环境和（托管）运行 URL 与作业结论；当落地的可执行内容与被门禁的提交不同时重跑受影响的套件。
- [ ] 任何未运行的必需套件都记录为 `NOT RUN` 并写明原因、替代验证和剩余风险；在它通过之前交付保持未完成。

---

## 6. 提交

- [ ] 一个逻辑变更，或对清晰分离的单元做聚焦提交。
- [ ] 没有机密、本地数据、`node_modules/`、构建产物、发布包或 CI 会重建的生成文件。
- [ ] 常规消息 `type(scope): description`；主题、空行、然后说明为什么的正文；相关时使用 issue trailer。
- [ ] 已审查 `git diff --stat`；按显式路径暂存文件并在暂存后重新检查 `git status`。
- [ ] 没有 force-push，也没有 `AGENTS.md` 中的硬禁止命令。

---

## 7. Pull/Merge Request

- [ ] PR 打开或更新前 `pnpm check:pr-base` 通过；PR 面向 `main` 且只含本任务的变更。
- [ ] 描述说明受影响的规格、E2E 场景和验证结果。
- [ ] PR 自审、必需检查（含 PR-base 门禁）和审查均已通过。
- [ ] 只执行了获授权的 push、合并和发布动作；真实阻塞被报告而不是被绕过。

---

## 8. 合并清理

- [ ] 已在本地 `main` 中核实预期提交或等价变更；请求远程交付时也在远程 `main` 中核实。
- [ ] 移除前已可恢复地归档请求内容；未保存数据和必要的忽略工件得到保留。
- [ ] 没有运行中的任务、服务或所需路径仍在使用该检出；保留的检出按确切路径报告。
- [ ] `git worktree remove` 在未强制的情况下成功；`git worktree prune` 未留下本请求的陈旧条目。
- [ ] 已合并任务分支用 `git branch -d` 删除；远程分支仅在明确授权时删除。
- [ ] 恢复快照位于归档引用或已核实文件中，`refs/heads/` 下没有留下备份分支。
- [ ] 空的请求容器和过时集成分支已清除；`git worktree list`、本地分支和实际路径一致认为没有冗余请求资源残留。
- [ ] 清理与合并在同一任务中完成，未为本请求自己的资源再次申请批准。
- [ ] 主检出、活跃工作和其他任务的资源得到保留。
- [ ] 交付后要求启动：已从已集成的 `main` 检出构建并启动应用。

---

## 9. 发布检查清单（稳定标签）

仅文档工作和非发布杂务跳过此节；[发布操作手册](/zh-CN/spec/06-delivery/06-release-runbook#_4-1-强制发布版本面门禁-d164-d260) 拥有该流程。

- [ ] `packages/shared/src/plus-changelog.ts` 为每个已发货语言提供该版本的最新在前条目，亮点条数对齐，英文是唯一事实来源。
- [ ] 条目是简短面向用户的产品说明，不是原始 PR 或提交列表；仅预发布版本被省略，除非产品明确为该渠道交付应用内说明。
- [ ] `packages/shared/src/changelog.test.ts` 将新版本列在首位；`pnpm --filter @pi-desktop/shared test` 通过。
- [ ] `README.md` 与 `README.zh-CN.md` 声明当前发布版本线，且没有本次发布推翻的说法。
- [ ] 打标签前 `node scripts/check-release-docs.mjs` 通过；发布文档已提交在发布分支上。
- [ ] 安装包只在 GitHub 托管的 Actions 上构建，包括 `pack --dir`；没有本地打包回退。
- [ ] 标签工作流使用了干净、具备新鲜远程祖先关系且没有已存在标签的已合并提交；共享 CI 与完整资产检查通过；记录所运行的签名通道，非签名输出不构成 Gatekeeper 资格。
- [ ] 证据已保留：`release-manifest.json`、`SHA256SUMS`、源 SHA 与基础 SHA、运行 URL，以及全部作业结论。
- [ ] 正式发布使用 草稿 → 上传 → 远程摘要与大小核实 → 发布；未覆盖任何已发布资产，失败的草稿被保留，任何重试都匹配其确切的来源与 manifest 身份。
- [ ] 预发布源使用其命名的渠道，绝不成为 GitHub 最新；GitHub release notes 不是应用内来源。

## 10. 最终完成定义门

- [ ] 在交付范围内，所有适用的[完成定义](/zh-CN/spec/06-delivery/03-ai-development-workflow#_11-完成定义)条件都成立。
- [ ] T0 记录一行交付说明；T1/T2 撰写 `AGENTS.md` 要求的交付报告（行为变更、文件、已运行检查、跳过并标记为 `NOT RUN` 的检查、风险）。
- [ ] 按 §0 和 §0.1 记录链接 issue 与 pull request 的结果。
- [ ] 索引已更新（NAV、交付 README、规格 README、文档 README、BOARD）。
- [ ] 失败的门禁被报告为阻塞项，而不是被削弱。

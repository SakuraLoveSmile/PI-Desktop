# 17. asktool 互动问题

> **翻译说明：** 本页是与 [英文源规格](/spec/03-runtime/17-asktool-questions) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。


## 1. 目的

`asktool` 让模型暂停回合并询问用户一个或多个有界的
问题。它在 Agent、Plan 和 Goal 模式下可用，并且独立于
权限审批：不授权操作，无有效性
截止日期。

## 2. 请求形状

该工具接受非空 `questions` 数组。每个问题包含：

- `question`：提示文字；
- `options`：一个或多个可选答案标签；
- `multiSelect`：可选；如果为 true，则允许多个可选答案。

桌面卡总是添加一个额外的 `Enter another answer` 选项以及文本
场。该模型不需要向工具添加特殊的自由文本选择
论据。

## 3. 卡片交互

一次仅显示一个问题。为每个呈现一个小指示器
问题并使用三种状态：未回答、已回答和已跳过。选择一个
指标重新审视了这个问题。 `Next` 当存在答案时记录答案；
否则记录一个跳过。 `Skip` 显式记录跳过并前进。
`Decline all` 解决了跳过的每个问题。

没有计时器、倒计时或自动过期。该卡仍处于待处理状态
直到用户提交或回合停止。如果回合停止时
卡已打开，运行时会解决跳过的所有剩余问题。
同一条助手回复工具批次中后续的普通 asktool 调用也直接返回跳过结果，
不再登记新的等待请求或打开提问卡；结果标记为 `resolutionKind: "stopped"`。
普通平稳停止仍按 `completed` 结算，取消仍按 `aborted` 结算；
Team 托管提问和 `preserveRunningTools` 路径保持原有行为。

## 4. 工具输出

响应是返回到模型并持续存在的正常工具结果
工具行。对于每个问题，内容序列化为：

```text
question text：answer 1、answer 2
```

多个问题由 `\n---\n` 分隔。跳过或未答复
Question 保留问题文本并使用空占位符：

```text
question text：
```

这种格式是确定性的，保留问题顺序，并进行多项选择
无需将仅渲染器状态对象暴露给
模型。

## Team Lead 待回答问题（WP11）

只有专家团 Lead 的宿主绑定运行回合采用 30 分钟等待预算。问题由 Rust
持久化；超时转为待回答并中断当前回合，不作答、不自动批准、不完成 Goal。
原提问卡保留。及时回答返回当前工具并确认消费；迟到或重启恢复的回答以
`asktool-answer:<requestId>` 原子写入用户队列，开启认证的新用户回合。
它不继承旧执行令牌，需明确恢复或重新审批。队列满时保留问题；同一回答
重试幂等，改答冲突。停止/取消设置回合围栏，防止迟到注册。普通 asktool
和权限审批继续无期限；重启队列仍等待控制端连接后释放。
